ETH 资金追踪的四个核心问题

一句话：先把链上转账事实标准化，再用“地址 + 方向 + 资产 + 金额预算 + 时间锚点”作为搜索状态，逐层扩展；合约节点不扫全历史，而是回到进入它的交易做协议级解释。

1. 它怎么搜索

算法形态：按层推进的 BFS，但不是普通地址 BFS。队列元素是 branchState，唯一键包含地址、方向、资产模式、资产、锚定区块和进入交易哈希。

seed
  -> frontier（当前层）
  -> QueryTransfers（方向 + 资产 + 时间窗口）
  -> 按时间排序并消费 amount budget
  -> 生成 edge / node / next state
  -> next 成为下一层 frontier
方向查询窗口消费顺序含义
outblock >= entryBlock早到晚资金进入后，向后找去向
inblock <= entryBlock晚到早资金支出前，向前找来源

归因规则：每个分支携带可归因金额，候选边金额会被预算截断，所有候选累计不能超过进入金额。它是确定性的工程归因，不是账户模型下的逐币证明。

2. 它如何扩展

节点类型扩展方式
EOA检查所需区块覆盖；缺数据时任务管理器先同步该地址的所需时间窗口，再重跑 Trace。
已支持合约不扫合约历史；以 entryTxHash 分析 Transaction、Receipt、logs 和 internal transactions，将输入资产转换为明确的输出资产后继续。
未知合约保留到达边，停止为 ambiguous_conversion 或 unsupported_contract。
人工扩展只能从已有、非终点节点出发，一次指定一个方向；根据入边聚合资产、金额和时间锚点，再查询一跳并与根结果去重合并。

去重不是只看地址：visitedNodes 控制图节点数量；visitedStates 控制同一资金状态不重复入队；当前路径再次出现地址则保留闭环边，但不继续入队。

3. 怎么判定终点

类别典型 stopReason性质
业务终点terminal地址元数据、交易所/热钱包标签、WOO X 已知钱包
协议边界cross_chain_bridge已知跨链桥；当前不追目标链
无法安全解释ambiguous_conversion合约交易没有唯一、完整的资产转换证据
数据边界missing_data / high_frequency补同步仍失败，或记录量触发保护
自然结束no_matching_transfers当前方向、资产、时间窗口内无符合条件的事实
计算保护cycle / node_limit环路不重复扩展；全图最多 5,000 节点

关键区分：终点不是“坏地址”，而是“当前规则下不再扩展的边界”。风险标签、数据不完整和资源保护不能混成一个概念。

4. 如何解析协议

Transaction(from/to/value/input)
             + Receipt(status/logs)
             + internal transactions
             -> topic/ABI 解码
             -> 合约身份验证
             -> 证据一致性检查
             -> TransactionAnalysis（缓存，带版本和质量）
协议/事实解析与验证
ERC-20按 Transfer topic 解 indexed from/to 与 data amount。
WETH只接受 WETH 官方地址发出的 Deposit/Withdrawal，解释 ETH/WETH 切换。
Uniswap V3解 Swap 的两个有符号 int256；正数是 Pool 收入、负数绝对值是输出。再用 eth_call 读取 pool 的 token0/token1/fee/factory，factory 必须等于官方 V3 Factory；最后用 Transfer logs 唯一解析最终接收地址。
KyberSwap RFQRouter、Executor、Transfer、internal call 和 WETH 资金证据必须匹配，才生成完整 conversion。
THOR/MAYA按函数 selector 解 Router calldata 和动态 memo；THORChain 跨到 BTC 还要调用协议 API 与 Bitcoin 交易输出核验，memo 只代表意图。
BitTorrent Bridgecalldata、LockedEther 与 StateSynced 同时匹配才承认入桥；目标链执行未验证，所以质量仍为 partial。

当前代码边界

  • 仅自动追踪 ETH 和白名单 ERC-20：DAI、USDC、USDT、WETH。
  • Ethereum 主网 ETH 小于 0.01、USDT 小于 50 的边会被过滤；这与部分“无小额门槛”的设计文档不一致。
  • 同步配置默认每个 Etherscan action 5 万条；同步器另有 20 万条任务级硬保护。Trace 查询自身也以 5 万条作为高频边界。
  • depth 查询参数会被归一化为 0；自动 Trace 不是固定 N 跳，真正上限是终止规则和 5,000 节点。
  • 跨链桥通常只作为边界；THORChain/MAYAChain 的特定 ETH→BTC 路径存在额外验证能力，不能概括成通用跨链追踪。
