# Ethereum 外部数据源与链上语义

## Etherscan 地址历史

项目使用 Etherscan V2 的三个 account action：

| action | 项目语义 |
| --- | --- |
| `txlist` | 顶层交易的原生 ETH value |
| `txlistinternal` | 执行调用中的原生 ETH value |
| `tokentx` | ERC-20 `Transfer` 日志 |

分页参数和响应数量是外部索引器契约，不证明某地址已经拥有完整历史。客户端必须保存每个 action 的独立区块检查点，并在写入成功后推进。

当前业务保护值是每个 action 50,000 条。达到后保留部分事实、标记高频终点并停止继续请求。

官方参考：

- [Etherscan V2 API](https://docs.etherscan.io/v2-migration)
- [Normal transactions by address](https://docs.etherscan.io/api-reference/endpoint/txlist)
- [Internal transactions by address](https://docs.etherscan.io/api-reference/endpoint/txlistinternal)
- [ERC-20 transfers by address](https://docs.etherscan.io/api-reference/endpoint/tokentx)

## Ethereum RPC

`eth_getTransactionByHash` 提供交易本体，`eth_getTransactionReceipt` 提供执行状态和日志，`eth_getCode` 判断指定区块的账户是否有合约代码，`eth_getBalance` 返回指定观察区块的余额。

内部交易不是共识层独立签名交易，而是执行调用产生的 value 转移。需要调用树时应使用节点 Trace 能力；Etherscan 的 `txlistinternal` 是索引视图。

ERC-20 转移来自 Token 合约发出的 `Transfer` 日志，`contractAddress` 是资产身份，不是收款地址。

官方参考：

- [Ethereum JSON-RPC](https://ethereum.org/developers/apis/json-rpc/)
- [ERC-20](https://eips.ethereum.org/EIPS/eip-20)

## 工程边界

- Etherscan 用于地址历史，RPC 用于交易、Receipt、余额、合约身份和协议验证，两者不能互相完全替代。
- 当前余额必须在明确观察区块查询，不能用历史流入减流出推算。
- 地址级路径是有时间和金额约束的归因，不是 UTXO 式逐币证明。
- 高频、数据不完整和协议不明确必须作为可见状态，不得伪装为“没有交易”。
- 当前项目只支持 Ethereum；跨链桥只作为终点。
