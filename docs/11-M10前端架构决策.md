# M10 前端架构决策

## 决策摘要

| 主题 | 选择 | 主要代价 |
| --- | --- | --- |
| 图引擎 | React Flow + ELK layered | 首包较大，但布局确定、交互组件成熟 |
| 空间语义 | 种子居中，上游负跳数、下游正跳数 | 环路节点只能采用首次可达方向 |
| 跨链 | Ethereum/Base 泳道 + 确认式桥接边 | 不推断缺少双链事实的桥接 |
| 金额 | API 到视图全程字符串，聚合使用 `BigInt` | 不提供汇率和跨资产总额 |
| 边显示 | 默认按链、地址对、方向、资产和来源聚合 | 内部 ETH 与普通 ETH 不会被误合并 |
| 异步状态 | TanStack Query 可取消轮询 | 暂无 WebSocket 推送 |
| 鉴权 | 静态控制台公开加载，`/api/*` 受保护 | Bearer 仅保存在页面内存，刷新即丢失；也可由网关注入 |
| 部署 | Vite 构建，Go SPA fallback 同源托管 | 构建镜像需要 Node 与 Go 两阶段 |

## 图数据规则

节点 ID 为 `chain:lowercaseAddress`，避免同一地址在 Ethereum 与 Base 上冲突。上游和下游分别输入 ELK layered 布局，再以查询种子为原点合成；Base 节点增加垂直偏移形成链泳道。桥接边只取后端 `bridgeEdges`，前端不根据金额、时间或地址相同做推断。

同组事实边的原始整数通过 `BigInt` 相加，展示时才按 decimals 插入小数点。元数据不完整时展示原始值并标记“精度未知”。任何情况下都不把链上整数转为 JavaScript `number`。

## 已知限制

- 当前 ELK 与 React Flow 进入同一主包，构建后约 586 KiB gzip。后续可把图工作区动态加载并将 ELK 放入 Web Worker。
- 环形资金路径可能同时具备上游和下游含义；第一版使用从种子出发首次访问所得的有符号跳数，事实边本身不丢失。
- 图层级收起只改变浏览器显示，不改变或截断后端结果。
- 后端不会返回低于 0.5 的传播推断；图工具栏的低置信度开关控制 `0.5 <= confidence < 0.7` 的推断视觉标记，不改变事实边或后端结果。
