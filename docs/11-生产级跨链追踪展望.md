# 生产级跨链追踪展望

## 1. 结论

生产级跨链追踪是未来 feature，不是当前 Demo 已完成的能力。

当前项目已经具备 Ethereum/Base 官方 OP Stack Bridge 的事件解析、消息标识关联和生命周期状态模型，可以围绕已知交易验证跨链证据。但它还不是持续运行的双链索引系统，不能宣称已经完整覆盖历史桥接、实时桥接、链重组、协议升级或第三方桥。

现阶段产品边界是：

- 继续追踪 Ethereum 和 Base 各自链内的资金事实；
- 对已知官方桥保留有限的识别与证据展示能力；
- 没有足够双链协议证据时，在桥处终止自动追踪；
- 不按金额相同、地址相同或时间接近推断跨链关系。

## 2. 为什么暂不生产化

跨链桥不是一笔同时存在于两条链的交易。源链和目标链分别产生 transaction、receipt 和 log，系统还需要依据桥协议的消息标识将两边关联起来。

只追 Ethereum/Base 官方桥时，可以按已知合约和事件过滤日志，不需要下载两条链的全部区块，因此数据量可以控制。主要成本来自持续正确性：

- 同时维护两条链的数据水位和 RPC 可用性；
- 解析桥合约、消息合约和不同部署版本；
- 关联源链消息与目标链执行结果；
- 跟踪提款的证明、挑战期和最终化；
- 处理链重组、漏块、限流、重试和历史回补；
- 为每一种第三方桥单独理解其验证和结算模型。

这些能力需要独立的索引、状态同步和运维投入。当前项目的核心仍是有界的单链资金追踪，因此暂不扩大范围。

## 3. 未来生产方案

未来实现时，采用“单链事实分开采集，跨链消息单独关联”的方法：

```text
Ethereum RPC -> Ethereum 事件索引器 --+
                                         +-> 桥协议解析器 -> 跨链消息状态 -> 资金图
Base RPC     -> Base 事件索引器 --------+
```

### 3.1 双链事实采集

分别增量读取 Ethereum 和 Base 上已注册桥合约的 receipt 与 log，保存交易哈希、区块号、区块哈希、日志序号、合约、资产、金额和参与地址。

采集范围按桥合约地址和事件 topic 过滤，并保存每条链的同步检查点。地址查询读取本地索引，不在用户请求期间临时扫描大段历史区块。

### 3.2 协议解析

为每种桥实现独立 adapter。adapter 负责：

- 识别源链的锁定、销毁或提款发起事件；
- 提取协议定义的 message hash、withdrawal hash 或 nonce；
- 识别目标链的铸造、解锁、消息中继或资产支付事件；
- 校验链、合约、Token 映射、发送者、接收者和金额。

官方 OP Stack Bridge、流动性桥和聚合器的结算方式不同，不能用一个基于金额和时间的通用匹配器替代协议 adapter。

### 3.3 跨链关联

优先使用协议消息标识关联两侧事实：

```text
source receipt/log
        -> protocol message hash
        -> target receipt/log
```

Ethereum 到 Base 的存款需要确认目标链消息中继和资产最终事件。Base 到 Ethereum 的提款需要依次跟踪发起、证明、挑战期、最终化和资产释放。

只有两侧协议证据能够唯一对应时，才在资金图中建立跨链边。桥合约通常混合保管或结算多个用户的资产，不能把桥合约的所有出账作为源地址的普通下游继续 BFS。

### 3.4 生命周期状态

跨链记录应明确展示状态，而不是只有成功或失败：

```text
observed -> initiated -> relayed/proven -> finalized -> completed
                                      \-> failed
```

暂时没有发现目标链记录表示 `pending` 或 `unknown`，不表示失败。上游 RPC 不可用也不能改变协议状态。

### 3.5 可靠性

生产实现至少需要：

- 保存 block hash 并在链重组后回滚和重放派生结果；
- 使用幂等键避免重复事件和重复跨链边；
- 对实时追块之外的数据执行缺块检测和定期历史校验；
- 对未完成消息进行持久化调度，不能使用短周期普通错误重试代替；
- 版本化桥地址、ABI、Token 映射和 adapter；
- 显示数据水位、证据来源和完整度。

## 4. 分阶段范围

如果未来启动该 feature，建议按以下范围递增：

1. Ethereum/Base 官方桥，仅支持用户提供交易哈希的按需分析；
2. 官方桥双链增量索引和地址查询；
3. 历史回补、重组恢复和持续状态校验；
4. 根据实际需求逐个增加第三方桥 adapter；
5. 最后再评估聚合器、快速流动性桥和批量结算的资金归因能力。

每个阶段都应明确支持的链、桥、资产和起始区块。未支持的协议显示为未知桥交互，不生成猜测性的跨链边。

## 5. 对外表述

当前可以表述为：

> 项目已经实现 Ethereum/Base 官方桥的有限协议解析和证据模型，但生产级跨链追踪仍是未来 feature。完整实现需要双链增量索引、协议消息关联、提款生命周期同步、链重组恢复和协议版本管理。当前系统在证据不足时会停止在桥边界，不根据金额或时间猜测目标链交易。

不能表述为：

- 已经完整监听 Ethereum 和 Base 的全部桥接活动；
- 已经支持所有跨链桥和聚合器；
- 任意两笔同额跨链交易都可以可靠配对；
- 资金进入桥后仍能像普通账户转账一样逐笔追踪。
