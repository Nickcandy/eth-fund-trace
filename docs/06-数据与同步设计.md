# 06 · 数据与同步设计

## 数据来源

按地址调用 Etherscan API V2：

- `txlist`：地址参与的普通顶层交易；
- `txlistinternal`：合约执行产生的 ETH 内部转账；
- `tokentx`：ERC-20 `Transfer` 事件。

不自行扫描区块。`startblock`、`endblock` 只用于查询范围和增量游标。

`chain` 由请求和数据源配置提供，不能根据地址字符串推断。第一阶段固定为 `chain=ethereum`、`chainId=1`；同一地址在不同 EVM 链上可能代表不同账户活动。

## MongoDB 集合

### `transfers`

一条可参与图分析的资金边对应一个文档。普通 ETH、内部 ETH 和 ERC-20 都标准化到这里。

关键字段：

```text
chain, chainId, txHash, blockNumber, blockTime
from, to, assetType, asset, symbol, decimals
amount, tokenValue, source, traceId, logIndex
observedAt
```

约定：

- ETH 使用 `assetType=eth`、`asset=ETH`、`amount` 保存 wei 字符串；
- ERC-20 使用 `assetType=erc20`、`asset` 保存 Token 合约地址、`tokenValue` 保存原始数量；
- 金额不使用 `float64`；
- 内部交易保留父 `txHash` 和 `traceId`；
- ERC-20 转账保留 `txHash`、`tokenAddress` 和 `logIndex`。
- Etherscan V2 `tokentx` 未返回 `logIndex` 时，适配层根据交易哈希、Token、双方、数量和同内容出现序号生成稳定的负数索引；真实链上日志索引保持非负，二者不混用。

### `addresses`

保存地址元数据和同步状态：

```text
chain, chainId, address
isContract, isTerminal
historySyncedToBlock, latestSyncedBlock
lastSyncedAt, syncStatus, syncError
```

### `labels`

保存人工、公开名单和推断标签。人工标签允许任何地址添加，但必须记录来源、备注和时间。

### `sync_jobs`

记录一次同步请求的参数、状态、耗时、抓取数量和错误，便于重试和排查。

### `cross_chain_links`（多链阶段）

保存桥接流程的关联，不把它伪装成普通转账：

```text
sourceChainId, sourceTxHash, sourceAddress
targetChainId, targetTxHash, targetAddress
bridgeAddress, relationType, observedAt
```

只有通过已知桥地址、事件或可靠交易关联确认的记录才写入该集合。

## 唯一索引和查询索引

唯一键：

```text
transfers: (chain, txHash, source, traceId, logIndex, asset)
addresses: (chain, address)
labels:    (chain, address, type, source)
```

追踪索引：

```text
(chain, from, assetType, blockNumber)
(chain, to, assetType, blockNumber)
(chain, from, asset)
(chain, to, asset)
```

实际实现时应根据查询计划确认索引，避免无条件增加索引。

## 按需同步流程

```text
输入地址
  -> 查询 addresses 同步状态
  -> 缺失或过期时调用 Etherscan
  -> 分页、限速、重试
  -> 标准化并 upsert transfers
  -> 更新同步状态
  -> 从交易中提取邻居地址
```

已经同步的地址不重复请求；需要更新时从 `latestSyncedBlock + 1` 开始补抓。同步失败必须保留错误状态，不能伪装成成功。

## 数据规模控制

- Etherscan 分页设置上限；
- 单次追踪限制最大地址数和最大边数；
- 对热钱包、交易所等终点地址保留到达边但不继续扩展；
- 只保存标准化字段，原始响应如需保留应单独设置生命周期；
- 追踪结果第一阶段实时计算，不持久化旧结果。
