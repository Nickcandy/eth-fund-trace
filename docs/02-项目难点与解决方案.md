# 项目难点与解决方案

## 数据完整性

Ethereum JSON-RPC 不提供任意地址的完整历史，因此地址同步使用 Etherscan V2。系统分别维护 `txlist`、`txlistinternal` 和 `tokentx` 检查点，只在批量写入成功后推进水位。上游超时、限流、分页异常和取消会成为明确任务状态，不能转换成空结果。

单个 action 拉取到 50,000 条时停止继续请求，并把地址标记为高频终点。已写入事实保留，Trace 不再要求该地址拥有完整历史。

## 资金归因与图扩展

`trace-v1` 的状态包含地址、方向、资产、剩余金额、入口交易、入口区块和路径。下游只能消费入口之后的事实，上游只能消费入口之前的事实；所有分支金额之和不能超过可归因余额。

环路保留闭环证据但不重复入队。高频地址、确定性终点、已知跨链桥、未知合约、小额资金和缺失数据会给出明确 `stopReason`。

初始结果与用户手动扩展分离。前端不设 5 跳可见性上限；点击节点后按方向创建扩展任务，并把新边合并到当前图。后端任务仍使用节点、边、记录数和取消信号控制资源。

## 合约与协议语义

普通 Transfer 事实与协议解释分层保存。只有成功、完整且身份验证通过的 Swap/Wrap 证据才允许改变追踪资产；不根据 calldata 外形或金额相近猜测协议行为。

Swap 在 UI 中表现为一条双向交换关系，而不是两条看似独立的单向资金边。

THORChain 解析器识别 Router、Vault、Memo 和真实出站。连续 `MIGRATE` 属于协议运维迁移，可折叠；Router 是协议边界而不是资金最终归属，用户可以从真实接收地址继续展开。

跨链桥不做协议分析。命中已知桥身份时仅记录到达事实并以 `cross_chain_bridge` 终止。

## 标签、画像与风险

地址画像是行为特征，不等于实体身份。人工标签和公开名单标签是确定性资料，保留来源、置信度和证据。

`direct-label-v1` 只读取查询地址自身的确定性标签。系统不做多跳标签传播，不根据交易邻接关系给地址继承 `hacker`、`exchange` 等身份，也不保存推断风险关联。

## 可恢复性

同步和 Trace 使用持久化任务状态，并支持停止当前工作。旧的非 `trace-v1` 结果不进入当前页面；不兼容任务应直接删除后重跑，而不是在读取时升级。

结果必须区分 `succeeded`、`partial`、`failed` 和 `stopped`。终点、数据不足和上游失败是不同语义，前端必须明确显示。
