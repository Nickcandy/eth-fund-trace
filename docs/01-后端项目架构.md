# 后端项目架构

## 系统定位

当前生产版本是 Ethereum 单链、只读的资金追踪服务。唯一可展示和扩展的分析结果版本为 `trace-v1`。

系统保存 Ethereum 地址历史和交易语义，输出可回查的资金事实、关系图、地址画像、直接标签风险和明确终点。它不支持 Base，不执行跨链关联，也不做标签传染。

## 模块

```text
React 控制台
    |
Echo HTTP API
    |
    +-- syncer ---------------- Etherscan V2 地址历史
    +-- tracer ---------------- trace-v1 与手动扩展
    +-- transactionanalysis --- Receipt、Transfer、Wrap、Swap、THORChain 语义
    +-- profile ---------------- 地址活动画像
    +-- risk ------------------- 仅查询地址的直接标签
    |
MongoDB ----------------------- 事实、任务、标签、画像与分析缓存
Ethereum RPC ----------------- 交易、Receipt、余额、合约身份与日志
```

`cmd/server/main.go` 是组合根。HTTP Handler 通过窄接口调用领域服务，不直接访问 MongoDB Collection 或上游 API。

## 数据模型

三类 Etherscan 地址历史统一保存为 `Transfer`：

| 来源 | 语义 |
| --- | --- |
| `txlist` | 顶层交易中的原生 ETH value |
| `txlistinternal` | 合约执行中的原生 ETH value 转移 |
| `tokentx` | ERC-20 `Transfer` 日志 |

事实唯一键为 `(chain, txHash, source, traceId, logIndex, asset)`。金额始终以最小单位十进制字符串保存，计算使用 `big.Int`。

主要集合：

| 集合 | 内容 |
| --- | --- |
| `addresses` | 地址身份、同步覆盖和高频状态 |
| `transfers` | Ethereum 资金事实 |
| `sync_jobs` | 同步状态、检查点和进度 |
| `trace_jobs` | `trace-v1` 根任务和手动扩展任务 |
| `labels` | 人工或公开名单的确定性标签 |
| `address_profiles` | 地址活动画像 |
| `transaction_analyses` | 交易语义缓存 |
| `pool_metadata` | 已校验的 DEX Pool 元数据 |

已经删除 `cross_chain_links`、`propagation_jobs` 和 `inferred_risk_associations`，运行时不再创建这些集合。

## 运行链路

### 地址同步

同步器分页读取 `txlist`、`txlistinternal` 和 `tokentx`，批量幂等写入后推进检查点。任一 action 达到 50,000 条时，该地址标记为 `high_frequency`，保留已取得事实并停止继续拉取。

### trace-v1

`trace-v1` 从查询地址出发，按方向、资产、金额和入口区块消费逐笔事实。遇到未同步普通地址时先创建同步任务；遇到小额、环路、高频地址、未知合约、已知跨链桥或其他确定性终点时保留到达边并停止。

前端初始图可以很小。用户点击节点的上游或下游按钮后创建扩展任务；前端不再按 5 跳限制隐藏已返回节点。后端仍保留任务级预算，防止单次任务无界运行。

### 协议语义

交易分析支持 Ethereum Transaction/Receipt、ERC-20 Transfer、WETH、Swap 和 THORChain Router/Vault 语义。Swap 在图上作为一次双向交换关系展示。THORChain 运维迁移可以折叠，真实协议出站和最终接收地址可继续手动展开。

已知跨链桥只产生 `cross_chain_bridge` 终点分类。系统不查询目标链、不生成桥接边、不分析桥消息生命周期。

### 风险

`direct-label-v1` 只评估查询地址自身的 `manual` 或 `public-list` 标签。交易邻居不会继承标签，风险分不会沿图传播。终点判断可以使用确定性标签，但不会把关系推断写成新标签。

## API

当前路由以 [OpenAPI](openapi.yaml) 为准，主要包括同步、事实边、`trace-v1`、手动扩展、停止任务、交易语义、当前余额、地址画像和标签管理。Base、桥分析和传播任务 API 已删除。

## 边界

- 当前余额来自 Ethereum RPC 的指定观察区块，不使用历史流入减流出推算。
- Etherscan 地址历史是外部索引结果，不等价于完整执行 Trace。
- 账户模型中的资金可替代，路径是有证据的归因结果，不是逐币证明。
- 高频和终点是计算边界，不是风险标签。
