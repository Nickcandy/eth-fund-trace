# 07 · 追踪、打标与风险设计

## 三层职责

1. **追踪**：给定地址，找资金上游和下游，返回边、节点、路径和跳数。
2. **打标**：匹配人工/公开标签，并沿路径传播推断标签。
3. **风险**：根据确定性标签、直接/间接暴露、路径距离、资产和金额信号输出风险等级与原因。

追踪事实和风险结论分开，避免把“发生过一笔转账”直接等同于“地址有罪”。

## 地址画像与热钱包识别

热钱包识别是独立的地址画像 feature，位置在“数据入库之后、图追踪之前”：

```text
数据采集 -> 标准化入库 -> 地址画像 -> 标签/置信度 -> 图追踪剪枝 -> 风险分析
```

画像使用固定规则统计：交易频率、独立对手方数量、资金归集、批量转出、金额规模和 DeFi 交互比例。结果应输出 `suspected_hot_wallet` 标签及分数，记录规则版本和特征值。

只有已知或人工确认的 `exchange_hot_wallet` 才默认作为追踪终点；疑似热钱包默认继续展示和追踪，避免误剪枝。

## 分层批量 BFS

当前实现通过 `GET /api/v1/trace` 创建异步 `trace_jobs`。默认深度为 3、每跳 Top-N 为 10，最大深度为 5、最大节点数为 5000；未同步地址由追踪任务自动复用或创建 M3 同步任务。任务状态为 `queued -> waiting_sync -> running -> succeeded | partial | failed`。

不要为每个节点单独查询 Mongo。每一层维护一个 `frontier` 地址集合，使用 `$in` 批量查询：

```text
第 0 层: [A]       -> from in [A] 或 to in [A]
第 1 层: [B, C]    -> from in [B, C] 或 to in [B, C]
第 2 层: [D, E, F] -> from in [D, E, F] 或 to in [D, E, F]
```

每层依次执行：

1. 查询当前层所有相关边；
2. 按资产过滤；
3. 按金额或规则裁剪 Top-N；
4. 去除已访问地址；
5. 命中终点标签则保留边、不再扩展；
6. 形成下一层 `frontier`。

`frontier` 过大时分批执行 `$in`，例如每批 500 个地址。查询次数大致与深度和批次数相关，而不是与每个节点一一对应。

## 多资产和换币

ETH 和 ERC-20 是不同资产：

- 默认支持 `asset=ETH`、`asset=erc20` 或 `asset=all`；
- 本轮不生成同一父交易下的 ETH/Token 换币关联；资产传播保持独立，后续可插入关系适配器；
- 不直接相加 ETH 和 Token 数量；
- 第一阶段不做汇率换算和跨资产污点合并；
- 缺少 Token 转账数据时，返回“资产转换后数据不足”。

## 多链与 Layer 2

Ethereum Mainnet、Arbitrum、Optimism、Base 等网络分别维护自己的图。相同的 `0x` 地址在不同链上必须视为不同节点，节点身份至少是 `(chainId, address)`。

Layer 2 与主链可以通过桥交互，但不是普通的同链转账。第一阶段多链扩展需要：

- 为每条链配置独立的数据源和同步状态；
- 将主链桥存款、L2 铸造/释放、L2 提现和主链到账保存为跨链关联；
- 只有确认属于同一桥接流程时，才建立 `cross_chain_link`；
- 跨链关联记录原链、目标链、桥地址、父交易和关联时间；
- 不能因为两个地址字符串相同，就自动连接主链和 L2 的资金流。

跨链追踪的结果需要区分“同链资金边”和“跨链关联边”。在没有桥事件或可靠关联数据时，应报告“跨链路径数据不足”。

## 标签

标签至少包含：

```text
type, risk, confidence, source, note, evidence, createdAt
```

来源区分：

- `manual`：用户添加的人工标签；
- `public-list`：公开名单；
- `propagation`：由规则推断出的标签。

人工标签通过 `POST /api/v1/labels` 写入，`confidence` 为 0 到 1 的浮点数，`evidence` 为字符串数组。传播标签只返回在追踪结果中，不写入确定性标签集合。

标签传播采用固定规则和版本号。例如：

```text
hacker/phishing 下游第 n 跳 -> 疑似洗钱中转，1.0 * 0.8^n
hacker/phishing 上游第 n 跳 -> 疑似上游资金源，1.0 * 0.6^n
exchange/hot_wallet         -> 基础设施终点，不继续扩展
```

命中多个规则时使用固定的合并策略，低于阈值则不输出推断标签。

## 固定风险模型

第一阶段不做机器学习，使用版本化配置：

当前实现使用 `risk-v1`：高风险人工标签基准 70，普通风险标签基准 40；分数乘以置信度和距离衰减，70+ 为 `known_high`，40–69 为 `suspected`，低于 40 为 `no_conclusion`。本轮不计金额分，不跨资产换算。

```text
风险分数 = 标签风险
         + 直接/间接暴露分
         + 距离衰减分
         + 资产和金额信号
         - 低置信度惩罚
```

结果必须包含：

- `score` 和 `level`；
- 触发的规则；
- 关联标签；
- 关键路径和交易哈希；
- 使用的规则版本。

输出区分“已知高风险”“疑似关联”“暂无结论”，不将暂无结论解释为安全。
