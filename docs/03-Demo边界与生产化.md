# 当前范围与生产边界

## 当前唯一范围

| 维度 | 当前口径 |
| --- | --- |
| 网络 | Ethereum Mainnet |
| Trace 版本 | `trace-v1` |
| 交互 | 初始结果 + 节点上游/下游手动扩展，前端无 5 跳显示限制 |
| 同步保护 | 每个 Etherscan action 最多 50,000 条，达到后标记高频终点 |
| 风险 | `direct-label-v1`，只评估查询地址自身的确定性标签 |
| 跨链桥 | 只识别为 `cross_chain_bridge` 终点 |
| Base | 不支持 |
| 历史兼容 | 不升级旧分析结果；非 `trace-v1` 数据直接删除并重跑 |

## 已实现

- Ethereum 普通 ETH、内部 ETH 和 ERC-20 地址历史采集；
- 分页、重试、区间拆分、检查点、批量幂等写入和任务停止；
- `trace-v1` 的金额预算、时间边界、环路剪枝、终点判断和手动扩展；
- Transaction、Receipt、ERC-20、WETH、Swap 与 THORChain 语义；
- Swap 双向关系展示；
- 当前 Ethereum 余额查询；
- 人工/公开标签、地址画像和直接标签风险；
- 图节点、边、终点原因、任务状态和数据完整度展示。

## 明确不做

- Base 数据采集和展示；
- 跨链目标链查询、桥消息关联、桥生命周期和跨链图边；
- 标签传染、多跳风险传播和推断风险持久化；
- 旧结果升级；
- 根据同额、近时或同地址猜测同一笔资金；
- 把高频、合约或画像直接解释成违法身份。

## 生产约束

交互任务必须保持有界。前端可以无限次手动扩展，不代表单个后端任务可以无界扫描；每次扩展仍需受记录数、节点数、边数、超时和取消控制。

生产部署还需要补齐统一认证、租户隔离、分布式任务领取、集中 Provider 配额、链重组处理、监控告警、审计、备份恢复和容量压测。这些能力不改变当前业务口径。
