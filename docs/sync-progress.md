# 同步分页与进度

## 分页查询的对象

同步器对每个地址分别调用 Etherscan V2 的三个 `account` action：

- `txlist`：普通 ETH 交易；
- `txlistinternal`：内部 ETH 转账；
- `tokentx`：ERC-20 Transfer 事件。

每次请求还带有 `startblock`、`endblock`、`page` 和 `offset`。因此分页对象是“一个地址、一个 action、一个区块区间中的记录”，默认每页 100 条，最多读取 100 页（最多 10,000 条）。它与 Mongo 的资金边游标分页无关。

## 为什么旧实现看起来不写入

Etherscan 到达第 100 页时，客户端返回 `ErrPageLimit`。旧同步器只处理错误，没有处理错误中已经读取的切片；于是这一整段结果在内存中被丢弃，随后重新从区块区间二分查询。Mongo 在地址完成前也不会更新 `fetched`，所以前端同时显示为 0。

## 当前实现

客户端在页上限错误中保留已读取记录。同步器先写入能确认属于较早区块的记录，再从边界区块重新查询，并对剩余区间继续二分。边界区块可能被重复读取，但 Mongo upsert 保证幂等，避免因分页边界截断而漏记录。

同步任务的 `progress` 字段实时记录：

- 当前地址、action 和区块范围；
- 当前页、累计 API 页数；
- API 已读取条数与 Mongo 已写入条数；
- 区间拆分次数。

地址总数的完成百分比使用已处理地址数（成功、缓存或失败）；成功数单独展示。交易总数事前未知，因此页面不伪造“总交易百分比”。
