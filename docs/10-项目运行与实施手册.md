# 项目运行与实施手册

## 1. 系统边界

本项目是只读资金分析服务。输入 Ethereum 或 Base 地址后，系统从 Etherscan V2 拉取普通原生资产交易、内部原生资产转账和 ERC-20 `Transfer` 事件，写入 MongoDB，再执行画像、事实边查询、BFS 追踪、标签传播和固定规则风险评分。

系统不持有私钥、不广播交易、不扫描全链、不做汇率换算，也不会把“暂无结论”表达为“安全”。

## 2. 模块与数据流

```text
HTTP API
  -> syncer -> Etherscan V2 -> transfers/addresses/sync_jobs
  -> profile              -> address_profiles
  -> fundgraph             -> transfers 查询
  -> tracer -> syncer      -> trace_jobs
            -> risk        -> 推断标签与风险结果
  -> labels                -> labels
  -> bridge                -> cross_chain_links
```

- `internal/etherscan`：共享限流、重试、分页、三类响应标准化。
- `internal/syncer`：缓存、安全链头、区间拆分、幂等批量写入、邻居同步。
- `internal/profile`：`hot-wallet-v1` 画像快照。
- `internal/fundgraph`：正金额事实边、方向/资产过滤、稳定游标。
- `internal/tracer`：异步分层 BFS、Top-N、终点剪枝、同步依赖。
- `internal/risk`：`propagation-v1` 与 `risk-v1`。
- `internal/bridge`：有双链证据的确认式跨链关联。
- `internal/httpapi`：参数校验、错误契约和服务治理。

## 3. 数据建模

节点身份为 `(chain, chainId, address)`。当前链：

| chain | chainId | 数据源 |
| --- | ---: | --- |
| `ethereum` | 1 | Etherscan V2 |
| `base` | 8453 | Etherscan V2 |

资金边使用 `transfers` 集合。ERC-20 事件额外保存：

- `transferKind=transfer|mint|burn`；
- `transactionGroup=<chainId>:<txHash>`，只用于同父交易展示；
- `logIndexSynthetic=true` 表示上游未提供日志索引；
- `tokenMetadataComplete=false` 表示 decimals 缺失；
- 金额始终保存非负十进制整数字符串，避免溢出和浮点误差。

同父交易下的 ETH 与 Token 边仍是独立事实，不自动推导兑换。

Mongo 集合：`addresses`、`transfers`、`labels`、`sync_jobs`、`address_profiles`、`trace_jobs`、`cross_chain_links`。所有链上业务唯一键均包含 chain 或双链身份。

## 4. 配置

复制 `.env.example` 的配置到运行环境。主要变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `HTTP_ADDR` | `:8080` | 监听地址 |
| `HTTP_API_KEY` | 空 | 非空时启用 Bearer 鉴权 |
| `HTTP_TIMEOUT_SECONDS` | `30` | 单请求 Context 超时 |
| `HTTP_BODY_LIMIT` | `1M` | 请求体上限 |
| `HTTP_REQUESTS_PER_SECOND` | `20` | 单进程、按 IP 的 HTTP 限流 |
| `HTTP_BURST` | `10` | HTTP 限流突发量 |
| `MONGO_URI` | `mongodb://localhost:27017` | Mongo 地址 |
| `MONGO_DATABASE` | `eth_fund_trace` | 数据库名 |
| `ETHERSCAN_API_KEY` | 空 | Etherscan V2 Key |
| `ETHERSCAN_REQUESTS_PER_SECOND` | `5` | 两条链共享的单进程额度 |
| `ETHERSCAN_BURST` | `1` | 外部 API 突发量 |
| `SYNC_CACHE_TTL_MINUTES` | `15` | 地址同步缓存 |
| `SYNC_CONFIRMATIONS` | `12` | 安全链头确认数 |

限流均为单进程能力。多副本部署需要外部网关限流和分布式任务锁。

## 5. 启动

前置条件：Go 1.24、Docker、可用 Etherscan API Key。

```powershell
docker compose up -d mongo
$env:ETHERSCAN_API_KEY='your-key'
go run ./cmd/server
```

健康检查：

```powershell
Invoke-RestMethod http://localhost:8080/healthz
```

配置了 `HTTP_API_KEY` 时，API 请求增加：

```text
Authorization: Bearer <HTTP_API_KEY>
```

## 6. 标准业务流程

### 6.1 创建同步任务

```http
POST /api/v1/sync
Content-Type: application/json

{"chain":"ethereum","address":"0x...","startBlock":0,"neighborLimit":10}
```

响应 `202`。轮询 `GET /api/v1/sync-jobs/{jobId}`，直到 `succeeded|partial|failed`。首次同步到 `latestBlock-12`；15 分钟内复用缓存，过期后增量同步。

### 6.2 查询事实边和画像

```text
GET /api/v1/edges?chain=ethereum&address=0x...&direction=both&asset=all
GET /api/v1/addresses/0x...?chain=ethereum
GET /api/v1/addresses/0x.../profile?chain=ethereum
```

边只包含正金额事实。未同步地址返回 `409 address_not_synced`。

### 6.3 标签、追踪和风险

```text
POST /api/v1/labels
GET  /api/v1/labels?chain=ethereum&address=0x...
GET  /api/v1/trace?chain=ethereum&address=0x...&direction=both&depth=3&topN=10&asset=all
GET  /api/v1/trace-jobs/{traceJobId}
GET  /api/v1/risk?chain=ethereum&address=0x...&depth=3&topN=10
```

追踪始终异步。遇到未同步节点时自动创建或复用同步任务，状态进入 `waiting_sync`。独立风险接口针对已同步数据同步计算，并受 HTTP 超时约束。

### 6.4 Base 与桥接关系

同步和查询时将 `chain` 改为 `base`。相同 `0x` 地址在两条链上是两个节点。

确认桥接关系通过 `POST /api/v1/bridge-links` 导入，必须提供源/目标链交易哈希、日志索引、地址和至少一条外部证据。使用 `GET /api/v1/bridge-links?chain=...&address=...` 查询。系统不根据相同地址、金额或时间自动关联。

## 7. HTTP 契约

所有业务错误使用：

```json
{"error":{"code":"invalid_request","message":"...","retryable":false}}
```

每个响应带 `X-Request-ID`。主要状态码：`400` 参数错误、`401` 鉴权失败、`404` 资源不存在、`409` 地址未同步、`413` Body 超限、`429` HTTP 限流、`503` 队列/外部服务暂时不可用、`504` 请求超时。

完整路径和 schema 见 `docs/openapi.yaml`。

## 9. 性能与复杂度

- BFS 时间复杂度约为 `O(V + E)`，但受深度 5、节点 5000、frontier 批量 500、Top-N 20 限制。
- BFS 内存复杂度为 `O(V + E)`。
- Mongo 查询次数按层和 frontier 批次数增长，不按每个节点单独增长。
- 同步最坏调用量与地址历史长度、三类 action 和区间二分次数相关；高频地址可能超过免费日额度。

## 10. 故障处理

- `etherscan_rate_limited`：任务可重试；检查共享 5 QPS 和 API 日额度。
- `page_limit`：同步器会按区块区间二分；单块仍超限时必须换更完整的数据源。
- `interrupted`：服务重启会把遗留活动任务标记失败，调用方重新提交。
- `address_not_synced`：先提交同步任务并等待成功。
- Mongo 唯一键冲突：正常 upsert 不应发生；检查历史 schema 和索引是否一致。
- 跨链路径缺失：没有确认桥证据时属于数据不足，不应手工推断为已连接。

## 11. 安全与局限

- `HTTP_API_KEY` 是单共享密钥，只适合单团队/内网部署。
- API Key 不写入响应或日志；生产环境应通过 Secret 管理注入。
- 当前没有 TLS，生产环境放在反向代理或网关后。
- 当前任务队列和限流均在单进程内，多实例需要 Redis/消息队列和分布式锁。
- 风险结果是规则推断，不是法律或归属结论。
