# 05 · 实施计划

## 目标

实现一个只读的 Ethereum Mainnet 资金分析系统：按地址从 Etherscan 获取普通 ETH 交易、合约产生的 ETH 内部交易和 ERC-20 转账，保存到本地 Docker MongoDB，再进行上下游追踪、标签传播和固定规则风险分析。

系统不扫描区块、不发起交易、不托管资产；区块号只作为 Etherscan 查询过滤条件和增量同步游标。

## 实施顺序

| 阶段 | Feature | 主要产出 | 验收标准 |
| --- | --- | --- | --- |
| M0 | 工程和运行环境 | Go + Echo、配置、Docker MongoDB | 服务可启动，Mongo 可连接 |
| M1 | 数据模型和索引 | 地址、转账、标签、同步状态集合 | 索引创建成功，重复写入不产生重复数据 |
| M2 | Etherscan 数据适配 | `txlist`、`txlistinternal`、`tokentx` 分页客户端 | 固定地址可拉取并正确处理错误/限流 |
| M3 | 按需同步 | 地址同步服务和邻居发现 | 首次拉取入库，再次查询复用本地数据 |
| M4 | 地址画像和基础设施识别 | 交易频率、对手方、归集/批量转出等特征 | 输出疑似热钱包分数，不直接当作确定标签 |
| M5 | 标准化资金图 | ETH、内部 ETH、ERC-20 统一为资金边 | 可按地址、方向和资产查询边 |
| M6 | 分层批量追踪 | 双向 BFS、`$in` 批量查询、深度/扇出/终点剪枝 | 查询次数按层增长，不按节点增长 |
| M7 | 标签传播和风险 | 人工标签、推断标签、固定风险规则 | 返回分数、等级和可追溯原因 |
| M8 | HTTP API 和验证 | 同步、画像、追踪、地址、标签、风险接口 | 单元测试、集成测试和接口错误状态完整 |
| M9 | 多链/L2 扩展 | 链配置、链隔离、桥接关联 | Ethereum 与至少一条 L2 可独立同步和查询 |

## 每阶段执行原则

1. 先写能复现问题或验证行为的测试，再实现功能。
2. 每个阶段只引入当前需要的代码和依赖。
3. 外部 Etherscan 测试与图算法单元测试分离，单元测试不依赖网络。
4. 所有请求都传播 `context.Context`，设置超时和取消处理。
5. 每个阶段结束后运行 `gofmt`、相关 `go test` 和 `golangci-lint`。

## 第一批开发任务

按以下顺序开始编码：

1. 创建 `go.mod`、Echo 服务入口和配置加载。
2. 添加 `docker-compose.yml` 启动 MongoDB。
3. 实现 Mongo 连接、集合初始化和索引。
4. 定义 Etherscan 客户端接口及分页响应结构。
5. 实现普通交易、内部交易和 ERC-20 转账的标准化入库。
6. 实现 `POST /api/v1/sync`，用固定地址完成第一次端到端验证。
7. 基于入库数据计算地址画像，验证“疑似热钱包”不会自动替代人工标签。

## 明确留白

- 不扫描区块，不自建全链索引。
- 不做 NFT、跨链、机器学习、自动告警。
- 不把 ETH 和 ERC-20 强行换算为同一种金额。
- 不把“未发现风险”解释为“地址安全”。
