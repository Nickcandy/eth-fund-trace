Base / OP Stack：两条链与官方桥状态机

目标：理解 Base 虽然 EVM 兼容，却是独立链；跨链不能靠金额和时间猜测，必须以协议消息和双链事件建模。

上一课 · 下一课 · 知识地图

先记住结论

Ethereum 主网与 Base 有不同的 chain ID、区块、状态和合约地址空间。Base 是基于 OP Stack 的 optimistic rollup：交易先由 sequencer 排序并在 L2 执行，相关数据/承诺发布到 L1。官方桥是一套跨两条链传递消息的协议，不是数据库里把两条金额相等的转账连起来。

L1 deposit用户向 Ethereum 桥合约存入/发送消息
L2 relayBase 执行对应消息
L2 withdrawalBase 发起提款消息
prove在 L1 证明该消息
finalize满足条件后在 L1 最终领取

Deposit 与 withdrawal 不是镜像的即时操作

方向起点证据终点证据关键边界
Ethereum -> Base depositL1 Portal/桥事件或消息L2 对应 relay/到账仍要关联特定消息，不能只看金额
Base -> Ethereum withdrawalL2 withdrawal 事件/消息L1 prove 后 finalize需要经过证明与最终化；不是 L2 发出后立即可领

“Base 上看到转出”只能说明 withdrawal 已发起；“Ethereum 上有同额入账”也未必是其 finalization。状态应显式区分 observed、proved、finalized、failed/unknown，才能诚实表达生命周期。

官方桥识别的正确证据链

  1. 限定 chain 和该网络已知的官方桥/Portal 合约集合。
  2. 解析来自这些合约的协议事件或消息标识，而不是按地址名称匹配。
  3. 将 L1 与 L2 的消息字段、方向、资产和生命周期关联。
  4. 保留两侧 tx hash、block、log index 和验证状态，让用户可回查。

金额、时间接近和相同地址只能作为候选排序信号，不能升级为确定桥接边。Token 桥还可能涉及 L1 token 与 L2 representation 的地址映射，绝不能假设两个链上同地址就是同一资产。

最终性要按链和动作说

L2 receipt 成功说明该 L2 交易在当前 L2 链上执行成功，不等于 L1 资金已最终可领。对 optimistic rollup withdrawal，争议窗口和证明流程使最终化延后。反过来，L1 deposit 也涉及 L2 侧消息处理。系统应将“已观察到”、“已 relay”、“已证明”和“已最终化”分开显示。

项目落点

internal/bridge 保存官方桥识别与状态同步结果。它的输出应是带证据的跨链关系，而不是一条普通的同链资金边；查询失败或 RPC 不完整时应返回 partial/unknown，而非伪造终态。
