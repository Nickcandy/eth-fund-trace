ABI 公式

functionSelector = keccak256("name(canonicalTypes,...)")[0:4]
calldata         = selector || abi_encode(arguments)

topics[0] = keccak256("EventName(canonicalTypes,...)")
topics[1..] = indexed arguments
data = abi_encode(nonIndexedArguments)

Receipt 输出

字段能证明不能证明
status顶层执行成功/失败每个内部 call 都成功
logs成功执行留下的事件证据未发事件的所有状态变化
gasUsed本次交易使用的 gas单独决定总费用
contractAddress创建交易产生的合约地址普通调用的目标地址

失败语义

  • 顶层 revert：状态与 logs 回滚，transaction/receipt/nonce/费用仍存在。
  • 子调用 revert：子调用状态回滚；外层若捕获，可以继续并最终成功。
  • out of gas：调用失败并回滚对应调用帧，已消耗的 gas 不免费。
  • eth_call revert：RPC 返回错误或 revert data，不产生链上费用与状态。

高频面试短答

calldata 与 log 的区别：calldata 是调用前的输入，log 是成功执行过程中产生的输出证据。

event 为什么适合索引：indexed 参数进入 topics，节点可用 bloom/filter 检索；代价是动态 indexed 值通常只保留 hash，不能直接恢复原值。

为什么要 trace：receipt 不保留完整 call frame，无法展示内部调用路径、内部失败和所有 value 转移。

为什么金额用字符串/big.Int：EVM uint256/int256 超出 JavaScript 安全整数和 int64 范围；浮点数还会丢精度。
